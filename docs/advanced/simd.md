# SIMD Intrinsics

Utopia ships a full SIMD layer: fixed-size vector types lowered to LLVM
vector IR (`<4 x float>`, `<16 x i8>`, ...). Every backend (SSE/AVX/AVX-512,
NEON, SVE, RVV, ...) turns those into its native SIMD instructions, so one
API covers all architectures.

Three layers are provided (generated by `scripts/gen_simd_prelude.py`):

- **Portable** (`libs/prelude/lib/Simd/Core.utp`): `simd_*` functions for
  every vector type.
- **x86** (`Simd/X86.utp`): C-compatible `_mm_*`, `_mm256_*`, `_mm512_*`
  names (SSE/AVX/AVX-512).
- **NEON** (`Simd/Neon.utp`): AArch64 `v*_q` names.

## Vector types

| Width | Types |
|-------|-------|
| 128-bit | `float32x4`, `float64x2`, `int8x16`, `int16x8`, `int32x4`, `int64x2`, `uint8x16`, `uint16x8`, `uint32x4`, `uint64x2` |
| 256-bit | `float32x8`, `float64x4`, `int8x32`, `int16x16`, `int32x8`, `int64x4`, `uint8x32`, `uint16x16`, `uint32x8`, `uint64x4` |
| 512-bit | `float32x16`, `float64x8`, `int8x64`, `int16x32`, `int32x16`, `int64x8`, `uint8x64`, `uint16x32`, `uint32x16`, `uint64x8` |

Comparison results use mask types `boolx2` .. `boolx64` (`<N x i1>`).

## Portable layer

```utp
float32x4 a = simd_splat_f32x4(1.5);
float32x4 b = simd_splat_f32x4(2.5);
float32x4 c = simd_add(a, b);              // lane-wise add
float32x4 d = simd_fma(a, b, c);           // fused multiply-add

float32 s = simd_reduce_add(c);            // horizontal sum
float32 m = simd_reduce_max(c);

boolx4 mask = simd_cmp_lt(a, b);           // lane-wise compare
bool any = simd_any(mask);
float32x4 sel = simd_select(mask, a, b);   // lane-wise select

float32x4 sh = simd_shuffle(a, b, 3, 2, 5, 4);  // constant-index shuffle
float32 x = simd_extract(c, 0);
float32x4 ins = simd_insert(c, 1, 9.0);

float32x4 l = simd_load_f32x4(&buf[0]);    // aligned load (UB if misaligned)
float32x4 lu = simd_loadu_f32x4(&buf[1]);  // unaligned load
simd_store_f32x4(v, &buf[4]);
simd_storeu_f32x4(v, &buf[5]);
```

All ops are overloaded per vector type; binary/unary ops resolve from the
argument types, while shape/memory ops carry a type suffix
(`simd_splat_f32x4`, `simd_zero_i32x8`, `simd_load_f64x2`, ...).

Operation families:

- arithmetic: `add`, `sub`, `mul`, `div` (float), `sdiv`/`srem`/`udiv`/`urem`
  (int), `sqrt`, `neg`, `abs`, `fma`, `min`, `max`, `umin`, `umax`, `hadd`
- bitwise/shifts: `and`, `or`, `xor`, `not`, `shl`, `shr`, `ushr`
- comparisons: `cmp_eq`, `cmp_ne`, `cmp_lt`, `cmp_le`, `cmp_gt`, `cmp_ge`
  (signed/float) and `cmp_ult`, `cmp_ule`, `cmp_ugt`, `cmp_uge` (unsigned);
  `*_ones` variants return all-ones/zero vectors instead of masks
- selection/layout: `select`, `blendv`, `shuffle`, `extract`, `insert`,
  `splat_lane`, `splat`, `make`, `zero`, `unpacklo`, `unpackhi`, `movelh`,
  `movehl`
- memory: `load`/`loadu`/`store`/`storeu` (aligned variants are UB on
  misaligned addresses), `broadcast`
- conversions: `simd_convert_<target>(v)` between same-lane-count types
  (int<->float, float32<->float64, int widening/narrowing, bitcast for
  same-width pairs)
- reductions: `reduce_add`, `reduce_min`, `reduce_max`, `reduce_umin`,
  `reduce_umax`, `reduce_and`, `reduce_or`, `reduce_xor`
- masks: `any`, `all`, `bitmask` (packed lane bits)

## x86 layer (SSE / AVX / AVX-512)

C-compatible names over the same operations:

```utp
float32x4 v = _mm_add_ps(a, b);
float32x4 w = _mm256_fmadd_ps(a, b, c);
boolx16  k = _mm512_cmplt_ps_mask(a, b);
float32x4 m = _mm_set_ps(4.0, 3.0, 2.0, 1.0);   // element order like C
float32x4 z = _mm_setzero_ps();
float32x4 s = _mm_set1_ps(1.5);
float32x4 x = _mm_blendv_ps(mask, a, b);
int32    bits = _mm_movemask_ps(x);
float32x4 r = _mm_castsi128_ps(_mm_castps_si128(a));
int32x4  sh = _mm_slli_epi32(a, 3);
```

The `_mm_*` family covers `ps`/`pd` floats and `epi8/16/32/64` (+ `epu32`)
ints, `set`/`set1`/`setzero` construction, aligned/unaligned loads and
stores, comparisons (all-ones and AVX-512 mask forms), `mask_blend`,
`blendv`, `hadd`, `movelh`/`movehl`, `unpacklo`/`unpackhi`, casts,
conversions, `fmadd`, `extract`, `movemask` and `abs`.

## NEON layer (AArch64)

```utp
float32x4 v = vaddq_f32(a, b);
float32x4 w = vmulq_f32(a, b);
boolx4   m = vceqq_f32(a, b);
float32x4 d = vdupq_n_f32(1.5);
float32   s = vaddvq_f32(v);
float32x4 c = vcvtq_f32_s32(v);
int32x4   b = vreinterpretq_s32_f32(v);
```

SVE and RISC-V V need no separate layer: the portable ops already lower to
them on those targets (SVE uses scalable vectorization internally).

## Target features

The backend defaults to the baseline ISA (`generic`), which on x86-64 means
SSE2. To emit AVX/AVX-512 or a specific CPU, pass the feature flags:

```
utopia build . -O3 --mattr=+avx2
utopia build . -O3 --mattr=+avx512f,+avx512vl
utopia build . -O3 --mcpu=skylake-avx512
```

Without the right features the code still compiles and runs: LLVM legalizes
the vector IR to whatever the target supports (e.g. 256-bit vectors split
into 128-bit halves).

## Notes

- `shuffle` and `splat_lane` indices must be compile-time constants in
  `[0, 2 * lanes)`.
- Aligned `load`/`store` are UB on misaligned pointers (like `_mm_load_ps`);
  use the `*_u` variants otherwise.
- `new T[n]` arrays carry an 8-byte length prefix, so the user pointer is
  only 8-byte aligned; use `Memory.alloc(size, align)` for aligned buffers.
- Lane-count-changing conversions (e.g. `int8x16` -> `int16x8`) are not
  supported; widen via `shuffle`+`convert` or per-lane ops.
